## 架构

1. Rust 常驻的 libmpv 实例负责媒体网络请求、请求头、解复用、解码、缓冲、音频和播放状态；不会把已经解码的画面重新编码为视频传回浏览器。
2. Windows 原生视频层与 WebView UI 合成。先验证透明 WebView 上的 HTML 弹幕和控件完整可见，再决定是否可用原生嵌入；不接受视频子窗口遮挡弹幕、独立外置播放器或逐帧图片传输作为最终结果。
3. 前端保留原控制外观，通过适配层转发打开、停止、暂停、音量、静音、全屏和画中画操作；UI 状态由本次媒体代次对应的原生事件驱动。
4. 取流以房间元数据、可用画质、候选地址和请求头为边界。按 Simple Live 的实际平台算法逐项移植；Twitch 没有参考实现，保留 DTV 的平台查询并接入同一原生播放器。
5. 媒体操作串行、网络结果代次隔离。旧房间不再影响新房间；线路切换优先使用候选地址，不重复读取整个房间。初始化失败允许重试，关闭后释放上游连接和音频。

## Simple Live 对照项

- 初始化一次；缓存初始化 Future，失败清空后可重试。
- 内存缓存：cache-on-disk=no、cache-secs=8、cache-pause=yes、cache-pause-wait=2、demuxer-max-back-bytes=4194304、network-timeout=10。
- 原生硬解与兼容回退；HTTP headers 随每条媒体地址绑定，不共享可变的当前流地址。
- 房间与播放请求代次、媒体操作队列、3 秒错误复核、15 秒无进展缓冲检测、优先切备用线路、限次重试。
- 切房间和关闭取消计时器与旧请求，停止弹幕，清空旧画面；DTV 特有托盘播放规则保持原样。
